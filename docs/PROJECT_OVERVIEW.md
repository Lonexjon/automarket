# Automarket — что это и как работает

Этот файл — общее объяснение проекта для владельца: что мы строим, зачем,
как это работает изнутри, какие проблемы уже нашли и починили, какие
ограничения есть сейчас осознанно, и что дальше. Пишу как есть, без
приукрашивания — если что-то сырое или спорное, так и сказано.

---

## 1. Что это вообще такое

Агрегатор объявлений о продаже машин по Узбекистану. Идея: не хостить свои
объявления (это не Avtoelon/OLX), а **собирать чужие объявления из
Telegram-каналов, анализировать их и показывать: похожа ли цена на честную
рыночную, или продавец завышает/занижает**. Пользователь видит анализ и
ссылку на оригинал — сам контакт продавца и переписка остаются в Telegram.

### Юридическое ограничение (жёсткое, с самого начала проекта)

**Никогда не хостим напрямую контакты продавца или скачанные фото.**
Только анализ + ссылка на первоисточник. Это не пожелание, это правило,
на котором построена вся архитектура фото (см. раздел 5).

## 2. Почему так, а не иначе — ключевые решения

### 2.1. Только Telegram, не OLX/Avtoelon

Изначально пытались собирать также с OLX.uz и Avtoelon.uz. Оба сайта
блокируют датацентровые IP (подтверждено тремя независимыми способами:
headless Playwright, non-headless через Xvfb, и просто httpx — везде 404 с
IP сервера). Решение: прокси, которые разблокируют оба сайта разом, стоят
денег — **решили пока не покупать** (26.08.2026). Обсуждали также вариант
гонять скрапер с домашнего IP/ноутбука владельца — тоже отложили ("давай
пока tg доведём до идеала").

**Следствие:** ассортимент объявлений сейчас искусственно бедный и
однообразный (в основном Chevrolet — это то, чем реально торгуют в
узбекских Telegram-каналах). Это осознанное ограничение, не баг.

### 2.2. Regex вместо LLM для разбора текста

Раньше в проекте была явная договорённость не платить за LLM-экстракцию —
дорого при таком объёме. Вместо этого `parsers/regex_extract.py` разбирает
текст объявления регулярками (бесплатно). Компромисс:

- **Покрытие неполное.** Пост без понятного шаблона полей просто
  остаётся необработанным (кандидат для LLM «когда-нибудь», не сейчас).
  Из свежей пачки в 1148 постов regex понял только 275 — остальные 873
  просто лежат в сыром виде.
- **Точность не идеальна.** Regex не понимает контекст — легко путает
  первый взнос по рассрочке с полной ценой, если нет явного
  стоп-слова. Сегодня нашли и починили реальный такой случай (раздел 6).

Обсуждали переход на LLM (Claude Haiku 4.5 — самая дешёвая модель, ~$0.001
за один пост, то есть даже полный прогон всей новой пачки — центы) как
fallback только для того, что regex не разобрал, либо как QA-аудит уже
разобранного. **Пока не решили окончательно, идёт обсуждение.**

## 3. Архитектура: путь данных от Telegram до сайта

```
Telegram-каналы (29 шт, telegram_channels.md)
        |
        v  Telethon, инкрементально (только новые посты)
telegram_raw (сырой текст + фото/видео флаги)
        |
        v  regex, бесплатно
parsers/regex_extract.py
        |
        v  brand/model/year/price/mileage/city/phone + flags (авария, рассрочка, ...)
listings (таблица)
        |
        +--> tools/dedupe.py       -- схлопывает повторные посты одного продавца
        +--> tools/deal_score.py   -- цена относительно медианы сегмента
        +--> tools/fetch_telegram_photos.py -- прямые ссылки на фото с t.me/s/
        |
        v
api/main.py (FastAPI)  -->  web/ (статичный сайт: лента + карточка объявления)
```

### 3.1. Сбор (`parsers/telegram_ingest.py`)

Читает список каналов из кода (тот же список задокументирован в
`telegram_channels.md`). Для канала, который уже собирали, тянет только
посты новее последнего сохранённого `message_id` — не перекачивает всё
заново. Для нового канала — стартовый снимок (200 постов по умолчанию).

Видео-посты (некоторые каналы кидают объявление видео-сообщением вместо
фото+текста) не пропускаются молча — сохраняются с флагом `has_video`, но
если у видео нет подписи-текста, разобрать нечего (нужна была бы
транскрипция голоса — Whisper, обсуждали, пока отложили, см. раздел 7).

### 3.2. Разбор текста (`parsers/regex_extract.py`)

Понимает эмодзи-шаблон полей, которым пишет большинство каналов:

```
#Nexia 3
📅 Йили: 2020
👣 Пробег: 97000 km
💰 Narxi: 8700$
☎️ Тел: +998...
```

Плюс детектит «флаги» по ключевым словам в тексте — авария, покраска,
удар, требует ремонта, такси-использование, проблемы с документами,
залог/непогашенный кредит, **рассрочка** (см. раздел 6 — сегодня
переделали этот флаг). У каждого флага есть анти-отрицание: если рядом
с ключевым словом стоит «не», «без», «yo'q» (узб. «нет», важно: и
кириллицей «йўқ» тоже, это тоже сегодняшний фикс) — флаг не ставится,
потому что смысл перевёрнут.

### 3.3. Дедупликация (`tools/dedupe.py`)

Один и тот же продавец почти всегда постит одно объявление сразу в
несколько каналов. Группируем по
`(phone_hash, brand, model, year, mileage_km)` — без цены в ключе,
специально, чтобы ловить репосты с изменённой (обычно сниженной) ценой.
Из группы одно объявление остаётся «каноническим» (самое раннее), у
остальных проставляется `duplicate_of`. Если цена в группе отличается —
это пишется в `price_history`.

### 3.4. Оценка цены (`tools/deal_score.py`)

Считает медиану цены по сегменту `(brand, model, year)` среди канонических
объявлений с ценой в $. `deal_score = (медиана - цена) / медиана * 100` —
положительное число значит объявление дешевле рынка. Есть защита от
статистического мусора:

- цены ниже $1000 не участвуют в медиане вообще (почти наверняка не цена
  машины, а что-то другое зацепилось);
- цена меньше 35% от грубой медианы сегмента считается выбросом —
  не участвует и не получает свой deal_score;
- объявления с флагом `installment_price_mentioned` (рассрочка) —
  исключаются из медианы и не получают собственный deal_score.

### 3.5. Фото (`tools/fetch_telegram_photos.py`)

Не скачиваем фото к себе (юридическое ограничение, см. раздел 1). Вместо
этого берём прямую ссылку на CDN самого Telegram с публичной страницы
`t.me/s/<канал>/<id>` (эта страница не требует авторизации, специально
существует для встраивания превью на сторонних сайтах).

Две реальные ловушки здесь, обе нашли и починили сегодня (раздел 6):
1. Страница отдаёт несколько соседних постов для контекста — нужно
   вырезать именно блок нужного сообщения, а не брать первое попавшееся
   фото на странице.
2. Ссылки на CDN — с истекающим токеном. Через несколько дней та же
   ссылка отдаёт 404. Поэтому фото не «получил один раз и забыл» — нужно
   периодически переполучать.

### 3.6. API и сайт (`api/main.py`, `web/`)

FastAPI отдаёt JSON по контракту `openapi.yaml` (`/v1/listings`,
`/v1/listings/{id}`, `/v1/facets`, `/v1/stats`) и там же раздаёт статичные
файлы сайта. Сайт — лента объявлений с фильтрами + карточка объявления.

## 4. Автоматизация — что крутится само, без участия человека

На VPS (Vultr, `45.76.32.57`) стоит self-hosted GitHub Actions runner.
Три сценария:

| Workflow | Расписание | Что делает |
|---|---|---|
| `deploy.yml` | при каждом push в `main` | подтягивает код, ставит зависимости, перезапускает API |
| `pipeline.yml` | каждые 6 часов | сбор новых постов → разбор → дедуп → пересчёт deal_score → health_check |
| `refresh_photos.yml` | каждые 12 часов | переполучает фото (новые + протухшие ссылки) |
| `exec.yml` | по запросу | выполняет произвольную команду на сервере — это мой инструмент для диагностики и разовых скриптов, без необходимости владельцу печатать команды в консоль вручную |

`exec.yml` — временный dev-инструмент, не для продакшена. Он существует
потому что рабочая среда, откуда идёт разработка, не имеет прямого
SSH-доступа к серверу, а GitHub Actions на self-hosted runner — да.

## 5. Проблемы, найденные и починенные за последнюю сессию

Все — реальные баги на живых данных, не гипотетические.

1. **Дубли без учёта модели.** Старый ключ дедупа не включал `model` —
   Cobalt и Nexia от одного продавца с совпадающими ценой/пробегом/годом
   могли схлопнуться в одно объявление. Нашли 34 реальных случая на
   проде, починили ключ, разлепили старые ошибочные слияния.

2. **Рассрочка ломает цену.** Продавец пишет "рассрочка, первый взнос
   $4000" — regex вытаскивает $4000 как цену машины, deal_score думает,
   что это супер-выгодная сделка. Добавили флаг и исключение из расчётов.

3. **Чужое фото у объявления.** `t.me/s/` отдаёт несколько соседних
   постов — брали первое попавшееся фото на странице, иногда это было
   фото другого объявления. Починили вырезкой конкретного блока поста.

4. **Фото протухают.** Ссылки на CDN — с истекающим токеном, через
   несколько дней 404. Раньше фото получали один раз и никогда не
   обновляли — сайт со временем накапливал бы битые картинки. Теперь
   переполучаем каждые 12 часов автоматически.

5. **Флаг рассрочки на реальных данных не работал вообще (0 срабатываний
   за всё время).** Продавцы не пишут слово «рассрочка» — пишут
   `"Boshiga 2,000$ — 13 oyga 500$"` (первый взнос — ежемесячный платёж)
   без отдельной строки с полной ценой. Расширили паттерн под реальную
   формулировку.

6. **Кириллическое отрицание не распознавалось.** `NEGATION_RE` понимал
   только латинское "yo'q", а кириллическое "йўқ" (та же частота
   использования) — нет. Из-за этого `"банк йўқ, насия йўқ"` (= нет
   банка, нет рассрочки — обычная полная цена) ошибочно ловилось как
   признак рассрочки. Это била по ВСЕМ флагам, не только рассрочке.

7. **Порча кириллицы при пуше через GitHub API.** Обнаружил, что
   `push_files`/`create_or_update_file` API-инструмент иногда портит
   отдельные кириллические символы при передаче (например «Бозор» →
   «Бозар», «ў» → «џ», задваивал строки). С этого момента пушу изменения
   через обычный `git push`, а не через API — байты передаются точно.

## 6. Текущие ограничения (осознанные, не забытые баги)

- **Только Telegram.** OLX/Avtoelon заблокированы, прокси не куплены.
- **Regex, не LLM.** ~24% новых постов вообще не разбираются (не подошли
  под шаблон), плюс точность разбора того, что понято, не идеальна.
- **214+ видео-объявлений без текста** в новых каналах
  (`oddiybola_avto`, `mashinalar_vodiybozor`, `doda_narx`) — вообще не
  попадают на сайт, нужна транскрипция голоса, решение отложено.
- **Сайт не готов к публичному запуску** (по словам владельца) — мало
  объявлений, сырой дизайн, недостаточно надёжные данные. Сейчас фокус
  на сборе данных и анализе цен, а не на публичном виде сайта.
- **Репозиторий на GitHub публичный** — до продакшена нужно закрыть.
